# Configuring Tzara

There are three main areas to consider.  One is the environment settings defined in the `.env` file.  When installing for the first time a template is used with some sensible defaults.  The other location is `app/config.py`.   And finally, the various `docker*.yml` files. 

Just about everything in `config.py` looks for a value in the `.env` file, and if it doesn't exist, it uses a sensible default or whatever value you've assigned. 

# .env

The `.env` file defines settings used by docker, and, to some extent, the python code, `config.py` in particular. 

The `.env` file already has a lot of stuff documented, so this is just the highlights. 

| Setting=Default | Description |
|----------------|-------------|
| `COMPOSE_PATH_SEPARATOR=:` | This should be semicolon `;` on Windows. This is the seperator you'll use if you want to change Ollama or LLM server settings |
| `COMPOSE_FILE=docker-compose.yml` | If you want to bring your own OpenAI server that runs outside of the container system, you'll addd docker-compose.external-inference.yml (Lemonade works).  If you have an AMD ROCm or Nvidia GPU, you can use those with special Ollama containers, and so you would add that here. If you already have an Ollama server running on your local computer or elsewhere on your network, you can use that instead of building a container for it.  You would append docker-compose.external-inference.yml after the OS appropriate seperator symbol. |
| `VAULTS_LOCATION=./app/vaults` | You may already have some Obsidian vaults on your machine.  Currently only one parent folder is supported, so each child directory in this location can be its own vault. |
| `HISTORY_LOCATION=./app/vault-history` | Tzara currently uses `git` for document versioning, and this is the location separate from your Obsidian vaults, but also needs to be a sibling. |
| `TZ=UTC` | Your timezone, handed to every container. It decides three things: when wall-clock agent schedules fire (`daily @ 4:30 pm` means *your* 4:30 pm), the zone every timestamp in Tzara is displayed in, and what `datetime.now()` returns inside a jupyter code cell. Leave it `UTC` and all three stay UTC - a page you save at 8:30 pm will appear in its history as 1:30 the next morning. Use a tzdata name like `America/Chicago` rather than a fixed offset such as `-0500`, so daylight saving is tracked for you. |
| `TZARA_TEMPLATE=default` | You can make your own templates. There are two included, `ocean` with a blue color scheme and `sage` with full width layout and muted green. This is the site-wide fallback - an individual vault can pick its own theme instead, see [Per-vault settings](#per-vault-settings) below. |
| `POSTGRES_PASSWORD=*(generated by setup script)*` | Postgres bakes this into its data volume the first time it starts and never re-reads it, so changing it later locks you out until you wipe the volume and start over.  `setup.sh`/`setup.ps1` write a strong random one for you, so normally you never touch it - only set it by hand if you copied   `.env.template` yourself instead of running setup. |
| `OLLAMA_MODEL=llama3.2:3b` | Your chat model. The default is deliberately small so it runs on modest hardware; swap in something bigger once you've confirmed everything works. Safe to change anytime. |
| `OLLAMA_EMBED_MODEL=embeddinggemma:300m` | Your embedding model, please **decide this before you index much.** Every vector Tzara stores is tied to the model that produced it, so switching embed models later invalidates your entire search index and forces a full reindex.   Changing the chat model above is free; changing this one is not.  You can experiment with different embedding models, but this one seemed to work well for me.  |


## Per-vault settings

Everything above is site-wide. A few settings belong to a *single vault* instead, and
those live in a `.tzara/config.json` file inside the vault folder itself - next to
Obsidian's `.obsidian/`. The file travels with the vault, so a vault synced to another
machine keeps its own settings, and a database reset never loses them.

| Key | Description |
|-----|-------------|
| `display_name` | The label shown in the vault switcher and on `/vaults`. Defaults to the folder name. |
| `default_page` | The vault's start page - where `/`, the vault name on its own, and the home link in the header all go. Defaults to `Main`. A page in a subfolder is fine (`notes/Index`). This page is also protected from being moved or deleted. |
| `template` | A theme folder name (`ocean`, `sage`, or one of your own). Overrides `TZARA_TEMPLATE` for this vault only. |
| `colors` | Up to four color overrides - `base`, `background`, `foreground`, `link` - applied on top of whatever theme the vault uses. The quickest way to tell at a glance which vault you are in, without writing a theme. |

A minimal example:

```json
{
  "display_name": "The Expanse",
  "default_page": "Campaign Hub",
  "template": "ocean",
  "colors": {
    "base": "#7c3aed",
    "link": "#0a7d4f"
  },
  "version": 1
}
```

### Editing these

The `/vaults` page has a settings panel for every vault - click a vault's name to
open it. It edits exactly the keys above, including a color picker for each of the
four colors. Clearing a field removes the key, so the vault falls back to the
site-wide default.

### About the colors

These are the same four values a theme file sets, so a vault palette is a theme
without the folder. `base` is the accent - nav bars, buttons, callouts - and every
other shade in the wiki is derived from it, so setting `base` alone recolors most
of the page. `link` is the link hue.

`background` and `foreground` have one rule worth knowing: **keep `background`
light and `foreground` dark, even if you use dark mode.** Dark mode does not have
its own set of colors; it reuses these two with their roles swapped, so a
dark-leaning `background` produces dark text on a dark page. Any color syntax CSS
understands works - `#7c3aed`, `oklch(0.55 0.14 150)`, `rebeccapurple` - and a
value Tzara cannot parse as a color is ignored, leaving that one slot on the
theme's value.

Edit it with any text editor and reload the page - changing these values needs no
restart. (Creating a brand-new theme *folder* is the exception: the list of available
themes is read once at startup, so restart the server after adding one.) A value Tzara
cannot use (a theme folder that does not exist, a `default_page` pointing outside the
vault) is ignored in favour of the site-wide default, so a typo here cannot take a
vault offline.

Note that Tzara does **not** read Obsidian's `.obsidian/` settings. Obsidian only
writes the keys you have changed from its defaults, so in practice those files are
nearly empty and there is little there to honour; `.tzara/config.json` is the single
place Tzara looks.


Agent subsystem (OFF by default - opt in once you understand it)
Tzara can run background agents (which defined as markdown files in the system vault). They are powerful (scheduled/event-triggered runs, staged writes, sandboxed custom Python tools). Leave these disabled until you’ve read the authoring guide; flip to true to enable. See app/config.py for the full semantics. Can also specify in .env.

| Setting=Default | Description |
|----------------|-------------|
| `AGENT_SCHEDULER_ENABLED=false` | Enable agent scheduler |
| `EVENT_TRIGGERS_ENABLED=false` | Enable agent event triggers |

run_python lets the CHAT agent execute LLM-authored code in the page kernel (approval-gated per block). Off by default because note text read via search could carry prompt-injection that steers that code. Enable only if you trust your vaults’ content.

| Setting=Default | Description |
|----------------|-------------|
| CHAT_ENABLE_RUN_PYTHON=false | In document or wiki chat, allow the `run_python` tool.  This tool allows the LLM to generate python for you to either accept or deny running it as a tool call. |


# config.py

There's a lot of stuff here and many of the configs here can also be specified in the `.env`.  These are config options you really should look at because they're the ones most likely to make an impact on your vault.

| Setting=Default | Description |
|----------------|-------------|
| `VERSIONING_NAME=tzara` | You can leave this as is, but if you want to `git push` your vault to some place upstream, then edit this. |
| `VERSIONING_EMAIL=@tzara.studio` | Same as above, this is just the email |
| `LLM_*=*varies*` | Look at these settings if you have not already put them in your `.env` file. |
| `AUTO_GENERATE_TAGS=True` | Automatically generate tags for documents after each save.  This helps with searching and semantic linking. |
| `AUTO_GENERATE_SUMMARY=True` | Automatically generate summary for documents after each save. This helps with searching and semantic linking. |
| `INDEX_DOCUMENT_FRONTMATTER_DEFAULT=True` | If no `Index` directive in frontmatter, default to this value |
